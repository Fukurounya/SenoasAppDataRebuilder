# App UserData ReBuilder

一个用于 Windows 的 AppData 目录备份与恢复工具。它把指定应用在 `%USERPROFILE%\AppData` 下的用户数据目录保存到其他位置，并在需要时按照保存记录恢复；即使原始 AppData 目录已经被删除，也可以重新创建并还原。当然，你也可以用于保存和还原任何其他目录。

适合这些场景：

- 重装系统、迁移电脑前备份游戏存档或软件配置。
- 测试、清理、重置环境前留一份可回滚的数据。
- 同一个应用需要保存多份不同时间点的数据。
- 在具有冰点还原的共用系统或设备上还原登陆令牌等用户数据（请您妥善保管自己的敏感数据）。

> 应用本身没有提供导出/导入功能，但数据都在 AppData 下。
> 程序不会自动监控目录，也不会定时备份；保存和恢复都由用户手动触发。

## 功能特性

- **两种保存方式**
  - 压缩：使用 WinRAR 命令行生成 `.rar` 单文件归档。
  - 不压缩：使用 Windows 自带的 `robocopy` 镜像复制整个目录。
- **6 档压缩级别**：所有挡位可选可用，对应 WinRAR 的 `-m0` 到 `-m5`。
- **完整性校验**：压缩归档会计算 SHA-256；恢复前再次校验 SHA-256，并调用 WinRAR/UnRAR 执行归档测试。
- **Data 记录**：在程序目录下维护无扩展名的 UTF-8 XML 文件，记录目录历史和每次保存/恢复的参数、结果、备份路径、SHA-256。
- **删除后仍可恢复**：只要 Data 和备份归档还在，即使原 AppData 目录已经不存在，也能按历史记录恢复并自动创建目录。
- **异目录恢复确认**：恢复到与保存记录不同的目录时，需要再次点击确认，降低误覆盖风险。
- **自动寻找常用目录**：根据内置 `radarlist` 中的目录名，在 `AppData\LocalLow` 和 `AppData\Roaming` 下递归搜索匹配目录。
- **多任务窗口**：保存和恢复都是非模态窗口，可以并行执行多个不冲突的任务；每个任务有独立进度、日志和中止按钮。
- **状态栏诊断**：显示主进程进度、当前任务进度、失败状态；点击状态文字可查看 Data、radarlist、WinRAR、UnRAR 的实际路径。

## 快速开始

1. 将程序放到一个有写入权限的目录，例如 `D:\Tools\AppDataRebuilder\`。
2. 确认 `AppDataRebuilder.exe` 和 `UnRAR.exe` 在同一目录。
3. 启动程序。状态栏正常时显示“就绪”或“后台无进程”。
4. 选择要备份的 AppData 子目录，再选择目标储存目录。
5. 设置是否压缩、压缩级别、是否保留时间戳/文件属性。
6. 点击“开始保存”。
7. 需要恢复时，从历史下拉框选择原目录，确认恢复目标，然后点击“开始恢复”。

> 如果状态栏提示“未找到 WinRAR，已使用 UnRAR，保存功能已禁用”，说明当前只能恢复，不能进行压缩保存。安装 WinRAR 后重启程序即可。

### 保存目标与恢复目标

- 从历史记录选择源目录时，`textBox2` 会自动显示该记录原来的目标储存目录，方便确认 `.rar` 或备份文件夹在哪里。
- 如果想恢复到其他位置，直接修改 `SDinputbox`，再点击“开始恢复”；第一次点击只会把按钮变成“确定恢复到异目录”，第二次点击才真正开始。
- 恢复时不要用“AppData目录”按钮重新选择恢复目标：该按钮会把当前路径当作新的源目录去查找记录。正确做法是先选历史记录锁定源记录，再直接编辑 `SDinputbox`。

`目标储存目录` 使用的是 Windows 文件夹选择器，只能选择文件夹，不会列出 `.rar` 文件。这是设计行为，不是缺陷。

压缩文件的实际路径记录在 Data 中。选择历史记录后，程序会自动定位：

- 压缩保存：`<目标储存目录>\<源目录名>.rar`
- 不压缩保存：`<目标储存目录>\<源目录名>\`

恢复时不需要手动选择 `.rar`。恢复窗口的日志区顶部会显示“备份文件：完整路径”，可以直接核对自动定位到的归档。

## 保存流程

### 1. 参数检查

点击“开始保存”后，程序会检查：

- 源目录必须存在。
- 目标储存目录必须存在。
- 源目录与目标目录不能重叠。
- 备份路径不能位于源目录内部。
- 压缩模式下，目标位置不能已经存在同名文件夹。
- 非压缩模式下，目标位置不能已经存在同名文件。
- 当前不能有其他任务正在读写相同或重叠的路径。

### 2. 压缩保存

勾选“压缩”时：

1. 在 `%TEMP%\Senoa\DataReBuilder\Cache\<任务ID>\` 下创建临时归档。
2. 调用 WinRAR 命令行，从源目录递归归档所有内容。
3. 归档参数包含：
   - `-r` 递归；
   - `-y` 自动确认；
   - `-m0`～`-m5` 压缩级别；
   - `-xCache\cache` 排除源目录下的 `Cache\cache`；
   - `-t` 创建后测试归档完整性；
   - 需要保留时间戳时追加 `-ts`。

> 压缩模式通过 `-ts` 保留时间戳；“保留完整文件属性”的 `/COPY:DAT`、`/DCOPY:DAT` 主要作用于非压缩的 robocopy 模式。
4. 计算临时归档的 SHA-256。
5. 把归档复制到目标路径。
6. 再次计算目标归档的 SHA-256，确认与临时归档一致。
7. 写入 Data 操作记录。
8. 删除本次任务的临时缓存目录。

最终文件为：

```text
<目标储存目录>\<源目录名>.rar
```

### 3. 不压缩保存

不勾选“压缩”时，使用 `robocopy` 把源目录镜像到：

```text
<目标储存目录>\<源目录名>\
```

使用的参数包括：

```text
/MIR /XJ /R:2 /W:2 /NP /NFL /NDL /NJH /NJS /MT:<自动线程数>
```

并根据选项追加：

- 保留完整文件属性：`/COPY:DAT /DCOPY:DAT`
- 只保留时间戳：`/COPY:DT /DCOPY:T`
- 都不保留：`/COPY:D`

> `/MIR` 是镜像模式：目标中多出来的文件会被删除。保存和恢复前都要确认目标路径正确。

## 恢复流程

### 1. 匹配记录

程序按源目录字符串查找最近一条可用于恢复的记录：

- 保存记录必须成功；
- 恢复记录即使失败也可以作为再次尝试的依据；
- 压缩记录必须带有 SHA-256；
- 备份路径不能为空。

如果没有可用记录，且最近一次保存失败，程序会提示“该源目录最近一次保存未成功，请重新保存后再恢复”。

### 2. 恢复目标

- 默认恢复到保存记录中的原始源目录。
- 如果该目录已经被删除，程序会提示“该目录已不存在，已匹配保存记录；恢复时会自动创建”，恢复时通过 `Directory.CreateDirectory` 重新创建。
- 如果恢复到不同目录，按钮第一次点击会变为“确定恢复到异目录”，第二次点击才会执行。
- 恢复目标不能位于临时工作目录中，也不能与备份路径重叠。

### 3. 压缩归档恢复

1. 校验备份归档的 SHA-256。
2. 复制归档到 `%TEMP%\Senoa\DataReBuilder\Cache\<任务ID>\`。
3. 再次校验缓存副本的 SHA-256。
4. 调用 WinRAR/UnRAR 测试归档（`t`）。
5. 解压到缓存中的 `Extract` 目录（`x -y -o+`）。
6. 用 robocopy 把解压结果复制到恢复目标，保留时间戳和文件属性。
7. 写入恢复记录。
8. 清理缓存目录。

### 4. 非压缩备份恢复

直接用 robocopy 把备份文件夹镜像到恢复目标，保留时间戳和文件属性。

### 5. 恢复阶段使用的设置

恢复使用**保存记录中的压缩方式、备份路径和 SHA-256**；复制阶段固定保留时间戳和文件属性，主界面上当前的压缩级别、时间戳勾选状态不会改变恢复行为。恢复记录会继承原保存记录的备份路径、压缩方式、压缩级别、SHA-256 和时间戳/属性设置。

| 项目 | 规则 |
| --- | --- |
| 源目录名 | 取源路径最后一段目录名 |
| 压缩备份 | `<目标储存目录>\<源目录名>.rar` |
| 非压缩备份 | `<目标储存目录>\<源目录名>\` |
| 保存目标 | 必须已存在，不能与源目录重叠 |
| 恢复目标 | 可以不存在，程序会创建 |
| 备份路径 | 不能在源目录内部 |
| 同名冲突 | 压缩时不能已有同名文件夹；非压缩时不能已有同名文件 |
| 并发任务 | 读写路径重叠时拒绝启动新任务 |

## Data 文件

### 位置

`Data` 位于程序 exe 所在目录，没有扩展名：

```text
<程序目录>\Data
```

开发运行时通常是：

```text
AppDataRebuilder\bin\Debug\net8.0-windows\Data
```

程序启动时读取 Data，并据此恢复历史目录和操作记录。如果文件不存在、为空或格式损坏，程序会重新创建一个空的 Data 文件；损坏时的错误信息会显示在状态栏提示和状态详情中。

> 建议定期备份 Data 文件。它本身不包含文件内容，只包含路径、参数和 SHA-256；但没有它就无法按记录找到归档。

### 结构

```xml
<?xml version="1.0" encoding="utf-8"?>
<AppDataRebuilder version="2">
  <History>
    <Directory>C:\Users\Alice\AppData\Roaming\SomeApp</Directory>
  </History>
  <Operations>
    <Operation type="Save"
               time="2026-11-25T18:00:00.0000000+08:00"
               source="C:\Users\Alice\AppData\Roaming\SomeApp"
               target="D:\Backups"
               backupPath="D:\Backups\SomeApp.rar"
               compressed="true"
               sha256="0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
               level="5"
               keepTimestamps="true"
               keepFileAttributes="true"
               restoreDestination=""
               success="true"
               error="" />
  </Operations>
</AppDataRebuilder>
```

### 字段说明

| 字段 | 说明 |
| --- | --- |
| `version` | 当前为 `2` |
| `History/Directory` | 历史源目录，最新的在前；写入时去重 |
| `Operation/@type` | `Save` 或 `Restore` |
| `Operation/@time` | ISO 8601 时间 |
| `Operation/@source` | 保存时的源目录；恢复记录沿用该值 |
| `Operation/@target` | 保存时的目标储存根目录 |
| `Operation/@backupPath` | 压缩时为 `.rar` 完整路径；非压缩时为备份文件夹路径 |
| `Operation/@compressed` | 是否压缩 |
| `Operation/@sha256` | 压缩归档的 SHA-256；非压缩记录可为空 |
| `Operation/@level` | 压缩级别 `0`–`5` |
| `Operation/@keepTimestamps` | 是否保留时间戳 |
| `Operation/@keepFileAttributes` | 是否保留完整文件属性 |
| `Operation/@restoreDestination` | 恢复操作实际写入的目录；保存记录为空 |
| `Operation/@success` | 操作是否成功 |
| `Operation/@error` | 失败原因，成功时为空 |

### 记录去重

操作记录以“源目录 + 目标目录”为去重键，同一组合只保留最新一条。执行恢复后，该组合的保存记录会被恢复记录替换，但恢复记录继承原保存记录的备份路径、压缩方式、SHA-256 等字段。

## radarlist 自动寻找

`radarlist` 是一个 UTF-8 文本文件，编译时作为嵌入资源打包进程序集；源文件位于：

```text
AppDataRebuilder\radarlist
```

程序在以下位置递归搜索匹配目录：

```text
%USERPROFILE%\AppData\LocalLow
%USERPROFILE%\AppData\Roaming
```

### 文件格式

每行一个条目：

```text
# 以 # 开头的是注释
// 以 // 开头的也是注释
SomeGame
SomeVendor\SomeApp
```

- 空行会被忽略。
- 只写目录名时，按文件夹名匹配。
- 包含 `\` 或 `/` 时，按相对路径结尾匹配。
- 搜索会跳过符号链接/联接点，避免目录循环。
- 无权限访问的目录会被跳过，不会中断整个搜索。

### 当前状态

`radarlist` 为空，或其不存在时，点击“自动寻找”会提示：

```text
radarlist 中没有记录目录名
```

需要自动寻找时，请把目录名写入 `AppDataRebuilder\radarlist`，然后**重新编译**。程序优先读取嵌入资源；只要嵌入资源存在，修改程序目录下的外部 `radarlist` 文件不会影响运行结果。

## 任务窗口与状态

保存/恢复任务在独立的非模态窗口中运行：

- 窗口标题包含操作类型、目录名和时间戳，避免多任务时重名。
- `HighProgress` 显示整体进度，`LowProgress` 显示当前阶段进度。
- 下方日志区显示每个阶段和错误信息。
- 可以点击“中止操作”取消任务。
- 成功后窗口自动关闭。
- 失败或中止后窗口保持打开，按钮变为“关闭”，方便查看日志。
- 主窗口状态栏会为每个运行中的任务显示独立进度条；单任务时额外显示百分比。
- 失败任务在状态栏显示红色 100%，直到对应任务窗口关闭。
- 主窗口还有任务运行时不能直接退出，需要等待任务结束或先在任务窗口中中止。

## 注意事项与限制

- 本工具只备份用户选中的目录，不是系统镜像，也不会备份注册表、程序安装目录或整个用户配置。
- 压缩保存不会设置密码，生成的 `.rar` 不是加密归档。如果数据敏感，请自行使用其他工具加密。
- 重复压缩保存到同一个 `.rar` 时，WinRAR 会更新已有归档；源目录中已经删除的文件可能仍留在旧归档里。需要严格快照时，请使用新的目标目录/文件名，或先移走旧归档。
- `/MIR` 会删除目标目录中多余的文件。恢复或保存前务必确认路径，尤其是恢复到异目录时。
- 恢复会覆盖目标中的同名文件；程序只在“恢复到不同目录”时要求二次确认，恢复到原目录不会额外确认。
- `radarlist` 是编译期嵌入资源，修改后必须重新构建。
- 程序目录必须可写；放在 `Program Files` 等受保护目录时，Data 可能无法创建。
- 并发任务只检查路径冲突，不提供全局队列；大量任务同时运行仍可能争抢磁盘 I/O。
- 没有定时备份、自动清理旧归档、归档加密、增量备份等功能。
- `UnRAR.exe` 是第三方工具，版权归 Alexander L. Roshal 所有。见此:[License](#license)

## 常见问题

### 开始保存按钮是灰色的

程序没有找到可用的 WinRAR 命令行工具。安装 WinRAR，或确认 `Rar.exe`/`WinRAR.exe` 在注册表、默认安装目录或 `PATH` 中，然后重启程序。点击状态栏文字可以看到检测结果。

### 为什么“目标储存目录”里选不到压缩文件

该按钮只选择文件夹。`.rar` 由 Data 记录自动定位；恢复窗口的日志区顶部会显示实际归档路径。详见“为什么‘目标储存目录’不能选中 `.rar`”。

### 删除 AppData 目录后还能恢复吗

可以，前提是：

1. Data 文件仍存在且包含该目录的记录；
2. 对应的 `.rar` 或备份文件夹仍存在；
3. 压缩归档的 SHA-256 与记录一致。

从历史下拉框选择已删除的目录，`SDinputbox` 会保留该路径，`textBox2` 会回填原目标储存目录；点击“开始恢复”后程序会重新创建目录并还原内容。

### 提示“没有找到该源目录的保存记录”

常见原因：

- 该目录从未成功保存过；
- 最近一次保存失败；
- Data 被删除、清空或重建；
- 路径与记录不同，例如盘符变化、目录被移动或重命名。

可以先重新保存一次，再执行恢复。

### 提示“备份归档不存在”

记录中的 `.rar` 或备份文件夹被移动、重命名或删除了。程序按 Data 中的固定路径查找，不会自动在全盘搜索；请把归档放回记录中的位置，或重新保存。

### 提示“SHA256 校验失败”

归档内容已经变化，可能被覆盖、损坏或替换。程序会拒绝恢复，以避免还原出错误数据。请使用未被修改的归档，或重新保存一份。

### 恢复到错误的位置了

恢复目标由 `SDinputbox` 决定，不是 `textBox2`。如果想把数据恢复到其他位置，请先修改 `SDinputbox`，第一次点击“开始恢复”后确认按钮变为“确定恢复到异目录”，再点击第二次。

### 自动寻找提示“radarlist 中没有记录目录名”

`radarlist` 为空。请编辑 `AppDataRebuilder\radarlist`，加入目录名后重新编译。详见“radarlist 自动寻找”。

### Data 文件损坏了

程序会尝试重新创建一个空 Data。这样历史记录会丢失，但已有的 `.rar` 文件仍然存在，可以手动解压，或重新保存建立新记录。建议平时备份 Data 文件。

### 任务窗口没有自动关闭

保存/恢复成功后窗口会自动关闭；失败或中止时窗口会保持打开，按钮变为“关闭”，方便查看日志。关闭窗口后，主窗口状态栏中的失败标记也会消失。
